Temuan

Empat temuan — A–C dari pemindaian pasif 29 April 2026, D dari disclosure lanjutan 28 September 2026 (versi redaksi). Bukti di bawah ini dikutip apa adanya dari laporan — termasuk URL yang saat ini kemungkinan sudah 404.

A

Riwayat Web Defacement & SEO Poisoning

Jejak injeksi konten perjudian pada subdomain USK

Tingkat keparahan: TINGGI

Ditemukan jejak injeksi URL ilegal (perjudian/togel) pada beberapa subdomain. Meskipun status HTTP saat ini mungkin menunjukkan 404 (Not Found), jejak ini menandakan bahwa penyerang pernah berhasil mengeksploitasi celah (seperti unrestricted file upload atau kerentanan CMS) untuk menanamkan direktori asing.

URL terdampak & indikasi ancaman

  • https://fkep.usk.ac.id/BABEJUDI/ Riwayat injeksi judi online
  • https://siakadup3ai.usk.ac.id/BABEJUDI/ Riwayat injeksi judi online
  • https://sibela.usk.ac.id/market/?kemajuan=Safnah Backlink togel / spam SEO
  • https://sippan.usk.ac.id/kejora/?perkara=KOI-TOTO-TOGEL-LOGIN Backlink togel / spam SEO

URL di atas ditampilkan sebagai teks bukti, bukan tautan aktif — sebagian sudah tidak lagi merespons saat laporan ditulis.

B

Eksposur Data Publik

35 alamat surel institusi fungsional terekspos secara publik

Tingkat keparahan: SEDANG

Pemindaian OSINT mendeteksi 35 alamat surel institusi fungsional yang terekspos secara publik. Data ini rawan dimanfaatkan sebagai vektor serangan Social Engineering maupun Spear Phishing yang ditargetkan pada staf atau dosen USK.

@usk.ac.id × 35 alamat

Alamat individual tidak ditampilkan di halaman ini — hanya agregatnya: 30 alamat di @usk.ac.id langsung dan 5 alamat di subdomain (feb, fkip, fmipa, mhs). Daftar lengkap 35 alamat ada di lampiran mentah untuk tim UPT TIK USK (full_hosts_scan_usk.txt, Bagian 1).

C

Pemetaan Subdomain / Attack Surface

893 subdomain/host aktif memetakan infrastruktur jaringan secara terbuka

Tingkat keparahan: SEDANG

Pemindaian pasif menemukan total 893 subdomain/host aktif. Beberapa di antaranya memerlukan perhatian khusus karena menunjukkan indikasi lingkungan pengujian (development environment) yang dapat diakses publik tanpa autentikasi dasar.

Aset berisiko tinggi

  • dev.fk.usk.ac.idlingkungan development Fakultas Kedokteran
  • perwaliandev.usk.ac.idlingkungan development sistem perwalian

Pemetaan lengkap 893 host dan alamat IP terkait dilampirkan secara utuh pada dokumen pendukung. Jelajahi daftarnya di bawah.

D

Eksposur Dump SQL Sistem Pembayaran H2H

171.235 transaksi + 15.000 PIN terekspos lewat direktori /db/ — h2h.usk.ac.id

Tingkat keparahan: KRITIS

Direktori /db/ di h2h.usk.ac.id (Apache 2.4.58, CodeIgniter) terekspos lewat autoindex: permintaan GET /db/ mengembalikan 200 beserta daftar berkas. Dua dump SQL lengkap ada di sana — h2h.sql (18 KB: skema + konfigurasi + kredensial pengguna) dan exubp.sql (24 MB: 171.235 transaksi pembayaran + 15.000 PIN). Temuan ini ditemukan 28 September 2026, setelah laporan 29 April 2026 — versinya redaksi (lihat pita di bawah).

Bukti

  • GET /db/ → 200 autoindex aktif, dua dump terdaftar
  • h2h.sql (18 KB) skema + konfigurasi + kredensial pengguna
  • exubp.sql (24 MB) 171.235 transaksi + 15.000 PIN
  • tb_user 3 akun admin, hash MD5 tanpa salt (disensor)
  • trx_data skema: trx_data_id, trx_time_stamp, bill_data_id, Channel_ID, Response_Code, Response_Message, Transaction_ID, Payment_Amount, event
  • pin_lib skema: autoid, pin_id, pin_pin, pin_paid_flag, reversed_flag, Transaction_ID, paid_type
  • tb_web_service endpoint API internal H2H (host internal disensor)
  • BSI — Bank Syariah Indonesia mitra bank aktif
× 3 akun admin — NIP + hash MD5 disensor

Nilai per orang juga tidak ditampilkan: NIK, PIN, nama pembayar, dan nilai transaksi contoh. Dua dari tiga hash MD5 berhasil di-crack karena password mengikuti pola yang mudah ditebak dari identitas pemilik akun — polanya yang harus dihentikan, bukan nilainya yang disebar.

Dampak

  • Eksposur massal data pribadi + keuangan: 171 ribu transaksi pembayaran + 15 ribu PIN.
  • Kredensial bocor: 3 akun admin memakai hash MD5 tanpa salt — bisa di-crack.
  • Pemetaan infrastruktur internal: endpoint API H2H internal membuka layout jaringan internal.
  • Potensi penipuan pembayaran: pustaka PIN + ID transaksi bisa diputar ulang / dipalsukan.
  • Pelanggaran regulasi: UU PDP — data keuangan + data pribadi terekspos publik.
  • Pengambilalihan admin terkonfirmasi: satu akun admin berhasil dipakai login lewat /login/dologin + /move/domove hingga mengakses dashboard admin penuh (mitra, tarif, laporan pembayaran, manajemen pembayaran, dan menu lainnya).

Reproduksi (generik, tanpa kredensial)

  1. Minta daftar direktori /db/ — autoindex mengembalikan 200 dan menampilkan dua dump SQL.
  2. Unduh dump h2h.sql dan exubp.sql dari /db/.
  3. Baca tabel tb_user dari h2h.sql — tiga akun admin dengan hash MD5 tanpa salt.
  4. Crack hash MD5 (pola password lemah) sampai mendapat kredensial login yang valid.
  5. Login lewat /login/dologin, lalu POST /move/domove — sesi berubah ke peran Admin.
  6. Akses dashboard admin (/public/laporanpembayaran dan menu lainnya); ekspor laporan per jenis pendaftaran mengembalikan tabel data pembayaran lengkap.

Remediasi

  1. Hapus /db/ dari web root segera.
  2. Putar semua kredensial di tb_user (paksa reset password — jangan pakai NIP sebagai password).
  3. Putar kunci API H2H dengan BSI.
  4. Audit log akses untuk unduhan /db/.
  5. Terapkan kontrol akses pada semua backup database.
  6. Naikkan hashing password (MD5 → bcrypt/argon2).
  7. Terapkan rate limiting pada endpoint login.
  8. Tegakkan HTTPS (saat ini masih bisa diakses lewat HTTP).
  9. Tambahkan token CSRF pada semua form.
  10. Terapkan manajemen sesi yang benar (rotasi saat login, timeout, ikat IP).

Dump SQL mentah tidak dilampirkan di repo ini — hanya temuan (versi redaksi) dan hitungan agregat. Baca temuan lengkap: findings/F-006-h2h-sqldump.md. Checklist redaksi yang dipakai: docs/templates/finding-template.md.

    Rekomendasi mitigasi

    Tiga langkah preventif yang disarankan laporan 29 April 2026, plus satu langkah dari temuan D (F-006, September 2026), berdasarkan security best practices. Status tindak lanjut di USK tidak diketahui dari laporan ini — situs ini tidak mengklaim satu pun sudah diperbaiki.

    1. 1

      Pemeriksaan integritas sistem (file auditing)

      Melakukan pemeriksaan menyeluruh pada direktori web fakultas yang tercatat memiliki riwayat defacement, guna memastikan tidak ada anomali atau skrip berbahaya (seperti backdoor/web shell) yang masih bersarang di dalam server.

      Diajukan dalam laporan

    2. 2

      Pembatasan lingkungan pengembangan

      Menerapkan pembatasan akses secara ketat (misalnya melalui implementasi IP Whitelisting atau VPN Campus) pada seluruh subdomain yang diperuntukkan bagi fase development dan testing.

      Diajukan dalam laporan

    3. 3

      Audit pemetaan DNS (DNS hygiene)

      Meninjau kembali daftar DNS records dari hasil pemindaian terlampir dan mempertimbangkan untuk menonaktifkan (deprovisioning) subdomain maupun layanan yang sudah tidak beroperasi guna memitigasi risiko Subdomain Takeover.

      Diajukan dalam laporan

    4. 4

      Penutupan eksposur dump SQL H2H

      Menghapus /db/ dari web root, memutar semua kredensial dan kunci API H2H, menaikkan hashing password dari MD5 ke bcrypt/argon2, dan mengaudit log akses unduhan dump — rincian 10 langkah ada di temuan D.

      Diajukan dalam temuan F-006
